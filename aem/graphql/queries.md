# GraphQL queries (register these as PERSISTED queries)

The app calls persisted queries by name (cacheable GET):
  {AEM_GRAPHQL_URL}/graphql/execute.json/{AEM_PROJECT}/{queryName}

## destinations-all
```graphql
query {
  destinationList {
    items {
      city
      code
      tag
      basePrice
      milesPrice
      emoji
      blurb
      region
      affinity
      image {
        ... on ImageRef { _publishUrl _path }
      }
    }
  }
}
```

## Registering a persisted query (example: destinations-all)
```bash
# PUT the query text to persist it under config "tap"
curl -X PUT \
  "$AEM_GRAPHQL_URL/graphql/persist.json/tap/destinations-all" \
  -H "Authorization: Bearer $AEM_AUTH_TOKEN" \
  -H "Content-Type: application/json" \
  --data-binary @destinations-all.graphql

# then it's callable as:
curl "$AEM_GRAPHQL_URL/graphql/execute.json/tap/destinations-all" \
  -H "Authorization: Bearer $AEM_AUTH_TOKEN"
```

Notes
- `destinationList` / `offerList` are auto-generated by AEM from the model API names `destination` / `offer` (List variant).
- If you model `image` as a plain URL text field instead of a Content Reference, drop the `image { ... }` selection and just select `image`.
- On the publish tier, persisted queries are typically open (no token). On author, pass a bearer token (see README).
